# 0.4.4 登录与群聊提及修复

## 群聊诊断

用户指定的新群已保存在回复名单中，不在群拒绝名单；发言人未被全局屏蔽。两条明确提及均被原核心保存为 `atMe=true`，触发原因为“被艾特”。两次模型会话都只有一轮，调用 `finish`，状态为 `noreply`，没有发送、没有报错。

模型收尾说明认为显示的群名片是“另一个账号”，并称消息“不是找我”。这说明协议提及识别已经成功，但模型把群名片与角色名字的差异误判为提及了别人。完整个人记录仅保存在被 Git 忽略的本地私有日志目录。

增加 Android 平台插件 `android-mention-identity`：使用原核心 `before-context` 钩子和动态提示片段，仅将协议明确确认的 `atMe=true` 本批消息标明为提及当前机器人账号。消息引用使用原协议 `mid`，不使用本地存档递增 ID。普通消息、其他人的提及、私聊、主动消息不添加此标记。保留人设、名单、概率触发、暂停和出站限频。未强制发送固定文本，也未重放历史消息。原 `src/`、`ui/`、`package.json` 无改动。

会话页把 `noreply` 显示为“模型未回复”，详情显示模型收尾原因。回复名单顶部增加保存按钮及未保存提示；其他配置刷新不再重置名单草稿。

## 登录入口与二维码

首页和检查页提供“QQ 登录”入口。登录页直接读取手机内 NapCat 4.18.30 的实际 `CheckLoginStatus`，每秒同步状态。使用本地 WebUI 认证，认证令牌仅留在应用私有内存。

未登录时显示最新二维码，并可通过 NapCat 官方 `RefreshQRcode` 获取新码。二维码按最新路径和内容 SHA-256 判断更新，处理相同修改时间的文件重写；读到半写入或过大图片时隐藏，避免回退显示旧码。二维码 URL 变化时等待图片内容变化，扫码等待确认期间禁用刷新。已登录时隐藏二维码和刷新按钮；打开登录页不会启用回复。旧检查页的时间戳缓存展示已移除，统一使用新登录页。

- 25 项 Android 单元测试通过，其中 4 项覆盖二维码同时间戳替换、新旧路径选择、半写入图片及大小限制；构建和 lint 通过，lint 没有错误。
- 25 项 Node 回归测试通过，新增测试覆盖群名片差异、其他账号提及、会话隔离、协议消息 ID 和原插件加载/系统提示构建流程。发送队列及暂停保护回归通过。

- 群与好友名单、活跃设置、人设、单群限频等用户配置保持一致。QQ 已连接，自动回复保持用户现有暂停状态，新插件已在实际核心加载并生效。
